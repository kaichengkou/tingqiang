# v0.8：安卓 App

所有数字来自电脑上的安卓模拟器，不是真手机：Android 16（API 36）x86_64 系统镜像，6 个虚拟核（i7-13700HX）、6 GB 内存，系统 WebView 133.0.6943.137。手机是 ARM 处理器，速度和内存都会不同，见文末「没有验证」。

## 手机网页组件的限制

这些限制决定了 App 的做法，都是实测的：

| 情况 | 结果 |
| --- | --- |
| 页面带上 COOP／COEP 头 | 头确实送到了，但 `crossOriginIsolated` 仍为 false，没有 SharedArrayBuffer。WebView 不支持跨源隔离，所以 WASM 只能单线程 |
| `navigator.gpu` | 存在，但模拟器拿不到适配器；真手机上是否可用未知 |
| 同时运行的 ONNX Runtime 实例 | 两个正常；三个时渲染进程在音高分析中崩溃（`mmap failed: Out of memory`），当时进程常驻内存约 1.1 GB，系统还有 3.2 GB 空闲。每次都能复现 |
| 不申请 INTERNET 权限 | 页面照常从安装包加载（拦截请求不经过网络）；外部地址被 CSP 和拦截双重拒绝 |
| 从系统文件选择器选的文件 | 是 content:// 文件，`size` 为 0 但能完整读出。导出练习包时会漏掉录音，按大小切片的读取全都出错。现在 App 先复制到自己的缓存再交给页面 |

由此：音高分析在手机上最多两个 Worker；减弱伴奏开始前先关掉空闲的音高 Worker；减弱伴奏改由 App 原生运行模型。

## 减弱伴奏

同一段 20 秒输入，在 App 里分别用两种方式运行（以 WASM 为基准比较输出）：

| 方式 | 耗时 | 伴奏信噪比 | 人声信噪比 |
| --- | --- | --- | --- |
| 页面里 WASM，1 线程 | 68.6 秒 | 基准 | 基准 |
| App 原生 ONNX Runtime 1.31.1，4 线程 | 9.3 秒 | 133.9 dB | 126.5 dB |

差异在浮点舍入量级，与 v0.7 电脑上各后端之间的差异相同。

30 秒合成片段：WASM 139.1 秒，渲染进程内存峰值 1.3 GB；原生 18.3 秒，渲染进程峰值 611 MB（模型移到了 App 进程里）。

真实录音《三家店》（112 秒 MP3，于魁智），原生：**58.7 秒**。导入后 0.3 秒可以播放，21.2 秒完成音高分析（两个 Worker）。分离结束后 App 进程 PSS 约 204 MB（模型已释放）。

传输方式：每一遍模型输入约 8 MB，页面分块转成 base64 交给 App，结果从 `/__model/<id>` 以二进制取回。模拟器里每遍的往返开销没有单独测，整段 30 秒片段的耗时已包含在内。

## 打开、保存和分享

`tests/android.mjs` 全部通过（237 秒，含真实录音）。它走的是用户会看到的系统界面，而不是直接调页面函数：

- 沙箱：没有网络、清单里没有 INTERNET 权限，页面源是 `https://appassets.androidplatform.net`，原生模型可用。
- 系统文件选择器：在「下载」里点中文名的录音，导入并分析。
- 锁屏和后台：播放中按 Home 键，12 秒内播放前进超过 10 秒；关屏同样。播放时前台服务类型为媒体播放，停止约 5 秒后结束；授予通知权限时通知内容是「正在播放 · 听腔测试」。
- 返回键先关设置窗口，再把 App 退到后台，回来页面原样；转屏不重新加载页面。
- 麦克风：系统询问后选「仅在使用该应用时允许」，录到一遍。永久拒绝后页面说明原因，「打开麦克风设置」进入系统的应用信息页。
- 导出练习包：「保存到手机…」进入系统保存界面，文件写入「下载」（1.78 MB，含录音）；「发送给…」打开系统分享面板。
- 打开方式：把 .tqproj 交给 App，在清空的练习库里导入成功，时长 1:00；从媒体库交来的录音能打开并开始分析。
- 页面进程崩溃后，App 自动重建页面并恢复上次练习。
- 减弱伴奏期间按 Home 键，15 秒内进度从 4% 到 25%，前台服务类型为媒体处理；通知内容是「正在减弱伴奏… 25%」。
- 跟着伴奏唱：在唱词一句上录一遍（模拟器麦克风是静音），合成回放正常。

发行版 APK 装在开发版上覆盖安装成功，上次的练习保留；冷启动到首屏 0.62 秒（`am start -W`）。

## 界面

手机宽度 360 和 411 CSS 像素下没有横向溢出，正文和按钮文字不小于 11 像素（唱词注音 10 像素），主要按钮约 40 像素见方。系统字体调到 130% 时，页眉和播放栏换行而不是被截断。横屏时播放栏固定在底部。

模拟器的做法，供重测：Google APIs x86_64 Android 16 镜像，6 核、6 GB，`-no-window -no-boot-anim -gpu swiftshader_indirect`，并设置环境变量 `QEMU_AUDIO_DRV=none`（声音不从电脑扬声器出来，模拟器里的音频照常计时）；测试开始时还会把系统音量调到 0。Windows 需要开启「Windows 虚拟机监控程序平台」，这台电脑已经开了。

## 回归

页面的改动（平台判断、导出、分离选项、手机样式）也影响网页版和 Windows 客户端，所以都重测了：

- 72 项单元测试通过，所有模块可解析。
- Chrome：browser、browser-pitch、browser-timing-lyrics、browser-studio、browser-singalong、browser-separation 全部通过。
- 重新打包的 Windows 客户端 0.8.0：同样六项全部通过（browser 第一次在连接调试端口时超时，新程序首次启动较慢，单独重跑两次都通过）；`tests/desktop.mjs` 的八项客户端检查通过。
- Python 服务的测试这次没有运行：测试用的虚拟环境被系统临时文件清理删掉了一部分。服务端只改了版本号，`python -m compileall` 通过。

Windows 打包改为直接使用 npm 已装好的 Electron（`electronDist`）。这次打包时代理连不上 GitHub，原来的方式会因为重新下载而失败。

## 没有验证

- **真手机**：ARM 处理器上的速度、内存和发热；不同厂商的 WebView 版本（国内手机多随系统更新）；后台策略更严格的系统（MIUI、ColorOS、鸿蒙 4 等）会不会仍然冻结或结束 App。
- 真实麦克风、耳机和蓝牙的延迟。模拟器的麦克风是静音，只验证了授权和录音流程。
- 显卡（WebGPU）路径：App 有原生模型时不走它；没有原生库的 32 位手机才会试，模拟器上没有适配器。
- 32 位手机：发行版只带 arm64-v8a，这类手机会退回 WASM 单线程。
- 应用商店上架、正式签名、从旧版本升级到用不同密钥签名的版本。
